# Журнал решений FlyBrain

Каждое решение: **что** решили, **почему**, какие были **альтернативы** и что из этого **следует**. Новые решения дописываются в конец; старые не стираются. Если решение отменено, у него появляется пометка «Отменено решением D-0xx».

Отдельно помечено **[ЧЕСТНОСТЬ]**: всё, где поведение или результат задаётся не коннектомом, а готовым контроллером, ручной настройкой или нашим упрощением.

---

## D-001. Папка проекта — `C:\Projects\FlyBrain`
*20.10.2026, фаза исследования*

**Решение.** Проект лежит по короткому пути, записанному только латиницей.

**Почему.** Имя пользователя Windows записано кириллицей («Вячеслав»), а временные папки лежат внутри профиля пользователя и имеют пути длиннее 260 символов. При проверке это сломало создание окружения Python: ошибка `WinError 267`. Менеджер `uv` тоже выдал ошибку при установке Python в папку с кириллицей. Сам Python после этого работал, но риск лишних сбоев остаётся.

**Альтернативы.** Папка в «Документах» — путь тоже с кириллицей. Работа только внутри WSL2 — лишняя сложность (см. D-003).

**Следствия.** Окружение `.venv` и данные лежат внутри `C:\Projects\FlyBrain`. Не переносить проект в папки с кириллицей в пути.

## D-002. Python 3.12 и менеджер `uv`
**Решение.** Используем Python 3.12. Окружение создаётся менеджером `uv` одной командой (`uv sync`). PyTorch берём в сборке под CUDA 13.0.

**Почему.** На машине есть Python 3.14 и 3.10. Но 3.14 слишком свежий: некоторые научные пакеты обновляются под него с опозданием. А FlyGym требует как минимум 3.12. Вариант 3.12 проверен: PyTorch, Brian2 и FlyGym на нём работают. `uv` сам скачивает нужный Python и все библиотеки и записывает точные версии в файл `uv.lock` — у вас повторится ровно то же, что проверено. Видеокарта RTX 5070 относится к новому поколению Blackwell (sm_120), и ей нужна сборка PyTorch под CUDA 12.8 или новее. Сборка `torch 2.14.1+cu130` проверена и работает.

**Альтернативы.** Conda — тяжелее, медленнее, исторически хуже работает с кириллицей в путях. Обычный `pip` + `venv` — больше ручных шагов.

**Следствия.** Отдельно ставить CUDA Toolkit не нужно: PyTorch приносит всё своё. Установленный CUDA 13.3 не мешает.

## D-003. Всё работает прямо в Windows, без WSL2
**Решение.** Мозг, эталон, сервер, браузер и (в M2) тело запускаются прямо в Windows.

**Почему.** Это проверено на машине (20.10.2026):
- PyTorch видит RTX 5070 и считает на ней;
- оригинальный код Shiu на Brian2 компилируется установленным Visual Studio Build Tools и работает;
- FlyGym 2.1 строит муху, считает физику и пишет видео.

**Альтернативы.** WSL2 с Ubuntu (уже установлен). Он понадобился бы, только чтобы запускать код Eon Systems (он только для Linux) или Brian2CUDA. Нам это не нужно.

**Следствия.** Меньше движущихся частей; пользователю не нужно учить Linux. WSL2 остаётся запасным вариантом.

## D-004. Коннектом FlyWire, версия 783
**Решение.** Используем последний публичный выпуск FlyWire — 783. Готовые для модели файлы берём из репозитория Shiu (`Completeness_783.csv`, `Connectivity_783.parquet`).

**Почему.** 783 — финальная опубликованная версия. Репозиторий Shiu официально её поддерживает. Eon Systems тоже работают на 783. В этих файлах: 138 639 нейронов, 15 091 983 пары «нейрон → нейрон», 54 492 922 синапса — совпадает с официальными числами FlyWire.

**Альтернативы.** Версия 630, на которой считалась сама статья (127 400 нейронов), — устарела. Собирать связи самим из полной таблицы синапсов на Zenodo (9,5 ГБ) — долго и даёт риск ошибки.

**Следствия.** Числа из статьи (посчитанные на 630) у нас будут немного другими. Поэтому:
- точное сравнение делаем с оригинальным кодом Shiu, запущенным на 783 (эталон, D-006);
- со статьёй сравниваем только качественно (D-018).

## D-005. Модель нейронов — ровно как у Shiu, без подгонки
**Решение.** Параметры не меняем. Потенциал покоя −52 мВ, сброс −52 мВ, порог −45 мВ. Постоянная мембраны 20 мс, синапса 5 мс. Рефрактерный период (время «отдыха» после спайка) 2,2 мс. Задержка синапса 1,8 мс. Вес одного синапса 0,275 мВ. Шаг расчёта 0,1 мс. Стимул — пуассоновские (случайные) импульсы весом 250 × 0,275 мВ: каждый такой импульс гарантированно заставляет нейрон выстрелить. У стимулируемых нейронов рефрактерного периода нет. Знак связи: ГАМК и глутамат тормозят, остальные медиаторы возбуждают.

**Почему.** Цель M1 — проверить, что мы воспроизводим опубликованную модель. Любая подстройка сделала бы проверку бессмысленной.

**Следствия.** [ЧЕСТНОСТЬ] Если стимул не даёт ожидаемой реакции, параметры не трогаем, а пишем результат в отчёт.

## D-006. Эталон — оригинальный код Shiu на Brian2
**Решение.** Для проверки запускаем **неизменённый** `model.py` из репозитория Shiu (коммит `91bdd1e`, лицензия MIT) на процессоре. Код скачивается скриптом; в наш репозиторий мы его не копируем.

**Почему.** Это «золотой стандарт»: им посчитана сама статья. Проверено: на этой машине он работает. Один повтор по 1 с занимает около 150 с вместе с построением сети. На стимул «сахар 100 Гц» он дал MN9 = 64 Гц на противоположной стороне и 45 Гц на своей.

**Следствия.** Эталонные прогоны (около 11 условий × 30 повторов) займут примерно 1,5–2 часа. Их делаем один раз и сохраняем (коммит C4).

## D-007. Свой движок на PyTorch для видеокарты
**Решение.** Пишем компактный движок на PyTorch, который считает ту же модель на видеокарте.

**Почему.** Сравнили варианты:

| Вариант | Видеокарта в Windows | Сложность | Лицензия | Вывод |
|---|---|---|---|---|
| Brian2 (как в статье) | нет, только процессор | низкая | CeCILL | слишком медленно для «живого» режима: ~150 с на 1 с |
| Brian2CUDA | официально только Linux | средняя | CeCILL | нужен WSL2 |
| GeNN / PyGeNN | да, но нужна сборка из исходников | высокая | LGPL | лишняя сложность |
| Код Eon Systems (`fly-brain`, есть вариант на PyTorch) | только Linux | — | GPL-2.0+ | нельзя копировать в MIT-проект |
| **Свой на PyTorch** | **да, проверено** | низкая (~300 строк) | наш MIT | **выбран** |

Черновой замер на RTX 5070 Laptop (одноразовый код, не входит в проект):
- прямой способ — 0,85 мс на шаг, то есть 1 с жизни мухи за 8,5 с;
- 30 повторов сразу — 47 с на все 30;
- со способом из D-008 — 1 с жизни мухи за 2,4 с.

Для сравнения, Brian2 на одном ядре — около 150 с.

**Следствия.** Правильность движка не принимаем на веру: сверяем с эталоном (D-006) по порогам из D-018. Детали порядка операций (когда приходят стимулы, когда нейрон «отдыхает») повторяем по коду Brian2.

## D-008. Приём «блок из 18 шагов» — точный, не приближение
**Решение.** Передачу сигналов между нейронами считаем пачкой раз в 18 шагов. Плюс записываем последовательность команд видеокарты один раз и потом просто повторяем её (CUDA Graphs).

**Почему.** Сигнал идёт от нейрона к соседу ровно 1,8 мс = 18 шагов по 0,1 мс. Значит, всё, что нейроны «выстрелили» за текущие 18 шагов, дойдёт до соседей только в следующих 18 шагах. Поэтому все 18 рассылок можно посчитать одним большим умножением, и результат будет **в точности** тем же. Замер: 0,41 мс на шаг без записи команд, 0,24 мс с записью — это 0,42 от реального времени.

**Альтернативы.** Обычный шаг за шагом — в 3,5 раза медленнее. Увеличить шаг расчёта до 0,5 мс — быстрее, но это уже другая модель; отвергнуто.

## D-009. Лицензии и что лежит в git
**Решение.**
- Наш код — MIT.
- В git **не кладём** ни данные, ни чужой код. Всё скачивается скриптом с закреплённой версией (коммитом) и проверкой контрольной суммы (SHA-256).
- Код Eon Systems (GPL-2.0+) не копируем и не переписываем построчно.
- Авторов данных указываем в README, в интерфейсе и в документах (условие CC BY 4.0).

**Почему.** Код Shiu под MIT совместим с нашим, но держать его отдельно надёжнее: эталон остаётся «чистым». Данные FlyWire под CC BY 4.0 разрешают использование при указании авторов. У таблицы аннотаций в репозитории нет файла лицензии — это приложение к статье в открытом доступе. Поэтому мы её не распространяем, а только скачиваем у себя. GPL требует, чтобы производный код тоже был под GPL, а это несовместимо с MIT.

## D-010. Типы и координаты нейронов — из таблицы аннотаций FlyWire на GitHub
**Решение.** Источник — файл `Supplemental_file1_neuron_annotations.tsv` из репозитория `flyconnectome/flywire_annotations`, коммит `a83b277`.

**Почему.** Сайт FlyWire Codex отдаёт файлы только после входа через Google и получения ключа доступа. Таблица на GitHub открыта и содержит всё нужное для 139 248 нейронов: класс, тип, сторону, медиатор, точку на нейроне и положение тела клетки. Проверено: в ней есть 138 625 из 138 639 нейронов модели.

**Следствия.** Координаты в таблице записаны в «вокселях» (кубиках изображения) размером 4 × 4 × 40 нм. Переводим в микрометры: x·0,004; y·0,004; z·0,04. У 14 нейронов модели аннотации нет — показываем их серыми, с подписью «без аннотации».

*Уточнено в D-025: у этих 14 нейронов нет и координат, поэтому в облаке их нарисовать нельзя; в списках и поиске они подписаны «без аннотации».*

## D-011. Снимки FlyWire зеркальные — отражаем ось X при показе
**Решение.**
- Сторону нейрона («левый/правый») всегда берём из таблицы аннотаций: там она указана со стороны самой мухи.
- При 3D-показе отражаем координату X, чтобы левые нейроны мухи были слева, если смотреть мухе в спину.

**Почему.** По данным FlyWire, исходные снимки мозга при съёмке оказались зеркально отражены. Подписи в аннотациях позже исправили, а координаты остались «зеркальными». В коде Shiu (2023) стороны названы по-старому. Проверено: сахарные нейроны, которые у Shiu названы «right hemisphere», в нынешней таблице помечены как `left`.

**Следствия.** В интерфейсе и документах пишем стороны по новой таблице, то есть со стороны мухи. Тогда выходит, что «сахар слева у мухи» сильнее включает MN9 справа — на противоположной стороне, как и в статье. Проверка глазами — в коммите C3.

## D-012. Стимулы — точные списки нейронов из кода Shiu
**Решение.** Кнопки «сахар», «горечь», «касание усика» включают ровно те нейроны, что в `figures.ipynb` статьи. Номера нейронов там из версии 630. Номера, которые не изменились в 783, берём как есть. Изменившиеся **не подменяем «похожими»**, а просто не используем:

| Группа | В статье | Нашлось в 783 |
|---|---|---|
| Сахар (хоботок, одна сторона) | 21 | 20 |
| Горечь | 21 | 20 |
| Вода | 18 | 18 |
| Ir94e | 18 | 18 |
| JO-CE (усик) | 70 | 69 |
| JO-F (усик) | 60 | 60 |
| JO-D/m (усик) | 16 | 16 |

**Почему.** Цель — сравнение со статьёй. Подмена «похожим» нейроном — это наша догадка, а не данные.

**[ЧЕСТНОСТЬ]** С 2023 года классификацию вкусовых нейронов уточнили. В нынешней таблице из 21 «сахарного» нейрона Shiu только 9 помечены как `sugar` и 2 как `sugar/low_salt`. Остальные — `high_salt/heavy_metal` (5) и `putative_attractive` (4). Мы сознательно используем список статьи, а в интерфейсе пишем: «сахар — по списку Shiu et al. 2024». Вариант «по современной классификации» можно добавить позже **отдельной** кнопкой с подписью.

## D-013. Стимул «надвигающаяся тень» — экспериментальный
**Решение.** Кнопка «тень» напрямую возбуждает зрительные нейроны LPLC2 и LC4 одной стороны (в данных 210 и 104 нейрона на обе стороны). Ожидаемый «исполнитель» — гигантское волокно (DNp01), нейрон реакции побега.

**Почему.** Глаза и обработки изображения в модели нет. LPLC2 и LC4 — нейроны, которые у живых мух реагируют на приближающийся объект. По коннектому именно они дают гигантскому волокну больше всего входов: справа 622 и 431 синапс, слева 458 и 374.

**[ЧЕСТНОСТЬ]**
- В статье Shiu этот опыт не проверялся. Сравнивать не с чем, кроме общей литературы.
- У живой мухи гигантское волокно получает много сигналов через электрические синапсы, а в коннектоме их нет.
- Правому волокну FlyWire предсказал медиатор «глутамат». В модели Shiu это делает его тормозящим для его *собственных* целей. На то, включится ли само волокно, это не влияет.
  *Исправлено в D-025: это неверно. В файле связей Shiu правое волокно возбуждающее (знак +1); глутамат указан только в нынешней таблице аннотаций.*
- Если волокно не включится, это нормальный итог эксперимента. Записываем как есть.
- В интерфейсе у кнопки значок «эксперимент» и пояснение.

## D-014. Стимул «касание усика» — нейроны Джонстонова органа из статьи
**Решение.** Кнопка включает группы JO-CE, JO-F и JO-D/m из статьи (в коде Shiu — `JON_all`, 146 нейронов; в версии 783 нашлось 145). Ожидаемые «исполнители» — aDN1 (в новой таблице тип `DNg62`), aDN2 (`DNge078`), aBN1 (`SAD093`). Для проверки Б6 отдельно запускаем только JO-CE и только JO-F.

**[ЧЕСТНОСТЬ]** Это не физическое касание, а прямое включение чувствительных нейронов усика. Типы JON в аннотациях подписаны как `wind_gravity` и `grooming`: одни и те же нейроны отвечают и на ветер, и на касание.

## D-015. Показ — в браузере (three.js), сервер — Python (FastAPI + WebSocket)
**Решение.** Сервер на Python считает мозг и примерно 25 раз в секунду отправляет в браузер список «выстреливших» нейронов. Браузер рисует облако точек на three.js со свечением (bloom). Файлы three.js кладём в проект: никакой сборки и Node.js не нужно.

**Почему.** В браузере проще всего сделать красиво: свечение, плавная камера, подсказки при наведении, панели. Работает в Edge или Chrome, которые уже есть в Windows. 139 тысяч точек для видеокарты — пустяк. Выбор точки под мышкой делаем через отдельный невидимый кадр, где каждая точка закрашена своим цветом-номером. Это надёжнее, чем считать лучи.

**Альтернативы.** Python-окна (napari, vispy, pygfx) — сложнее сделать подсказки и красивый интерфейс. Unity или Unreal — тяжело, отдельный язык, сложная связь с Python.

## D-016. Где рисовать точку нейрона
**Решение.** Точка ставится в положение тела клетки (сомы), если оно известно. Если нет — в «опорную точку» нейрона из таблицы (`pos_x/y/z`).

**Почему.** Сома — физически реальное место клетки, его легко объяснить. У 21 144 нейронов сомы в таблице нет. В основном это сенсорные нейроны: их тела лежат вне мозга, в органах чувств. Для них опорная точка — место на их отростке внутри мозга.

**Следствия.** Сомы мухи лежат «корой» по поверхности мозга, так что облако будет похоже на мозг с плотной оболочкой. Позже можно добавить режим «центр ветвления нейрона» по скелетам (5,4 ГБ, необязательно; см. PLAN_M1, C12).

## D-017. Скорость «живого» режима показываем честно
**Решение.** В углу экрана всегда видно, во сколько раз симуляция медленнее реального времени (ожидаем около 0,3–0,5×). Никакого «ускорения на глаз» за счёт выбрасывания шагов.

## D-018. Пороги проверки M1 зафиксированы до кода
**Решение.** Используем пороги из [BRIEF.md](BRIEF.md), раздел 5:
- **А** — движок против эталона Brian2 на 783: корреляция частот ≥ 0,95; совпадение наборов активных нейронов ≥ 80 %; ключевые нейроны ±15 % или ±3 Гц;
- **Б1–Б7** — качественные выводы статьи;
- **В** — эксперимент с тенью, без порога.

«Активный нейрон» — средняя частота за 30 повторов не меньше 1 Гц (то есть в среднем хотя бы один спайк за 1 с). Одно и то же правило применяется к обоим расчётам.

**Почему.** Пороги, придуманные после результата, легко подогнать. Модель случайна (стимул — случайные импульсы), поэтому спайк в спайк расчёты не совпадут. Сравниваем средние за 30 повторов, как в статье.

**[ЧЕСТНОСТЬ]** Если какой-то пункт не выполнится, отчёт `docs/VALIDATION.md` покажет это красным. Мы разбираемся в причине (ошибка в коде или свойство версии 783), но не подстраиваем модель.

## D-019. В покое мозг «тёмный» — это свойство модели
**Решение.** Без стимула все нейроны молчат, и в интерфейсе мозг тёмный. Рядом поясняем: «в модели Shiu нет спонтанной активности; живой мозг в покое не молчит».

## D-020. Тело (M2) — FlyGym 2.1 (NeuroMechFly v2), физика на процессоре
**Решение.** Для M2 берём FlyGym 2.1.0. Проверено в Windows: модель строится, считается и рисуется (0,5 с физики с записью видео — за 3,4 с). В модели есть суставы хоботка (rostrum, haustellum) и усиков (pedicel, funiculus, arista).

**[ЧЕСТНОСТЬ]**
- В FlyGym 2.x контроллеры ходьбы (центральный генератор ритма, гибридный с поворотами) входят только в учебные примеры, а не в сам пакет. Их придётся взять из примеров (Apache-2.0) — это **готовый контроллер**, не коннектом.
- Груминга (чистки усика) в FlyGym нет: движение лапки придётся задать вручную.

## D-023. Каркас проекта (C1): сборка, `doctor`, `run.bat`
*20.10.2026, коммит C1*

**Решение.**
- Пакет `flybrain/` лежит в корне проекта и собирается через `hatchling`; команда `flybrain` объявлена в `pyproject.toml`. Python жёстко 3.12 (`>=3.12,<3.13`, файл `.python-version`).
- PyTorch подключён из отдельного индекса `https://download.pytorch.org/whl/cu130` (`[tool.uv.sources]`, индекс помечен `explicit`, чтобы остальные пакеты не искались там). `uv.lock` фиксирует `torch 2.14.1+cu130`.
- `pytest` лежит в группе `dev` (ставится обычным `uv sync`).
- `flybrain doctor` печатает шесть проверок: Python, путь проекта, видеокарта, компилятор C++, место на диске, кодировка. Статусы: `OK`, `ВНИМАНИЕ` (работать можно), `ОШИБКА` (код возврата 1).
- Видеокарта проверяется не только по имени: делается пробное умножение матриц на ней. Так видно, что для карты поколения Blackwell (sm_120) в PyTorch есть готовый код. Нет видеокарты — это `ВНИМАНИЕ`, а не `ОШИБКА`: в C5 движок умеет считать на процессоре.
- Компилятор C++ ищется через `vswhere` (самая свежая версия MSVC), запасной путь — `cl` или `g++` из PATH. Реальная сборка Brian2 в `doctor` не запускается (долго); её проверит C4.
- Кодировка: `doctor` пишет и читает UTF-8-файл с кириллицей в имени и показывает, включён ли режим UTF-8 в Python. При запуске без `run.bat` этот режим выключен (системная кодировка cp1251), и это **не** ошибка: весь наш код всегда указывает `encoding="utf-8"` (D-021). Вывод программы переключается на UTF-8 сам.
- `run.bat` содержит только латиницу: после `chcp 65001` `cmd` неверно разбирает не-латинские символы в самом `.bat` (проверено: строки «разваливаются»). Русское сообщение «не найден uv» лежит в `scripts/no_uv.txt` и выводится командой `type`.

**Почему.** Нужна одна команда, которая за секунды говорит, готова ли машина, и понятно объясняет, что чинить.

**Альтернативы.** Определять видеокарту через `nvidia-smi` — не показывает, работает ли PyTorch. Считать выключенный режим UTF-8 предупреждением — сломало бы условие «все OK» для обычного `uv run`.

**Следствия.** На этой машине `uv` на момент C1 не был в PATH (он был установлен только как модуль Python 3.14); для обычной работы нужна команда `winget install --id=astral-sh.uv -e` (docs/SETUP.md).

## D-024. Скачивание данных (C2): суммы — от байтов GitHub, а не от файлов в `.research/`
*20.10.2026, коммит C2*

**Решение.**
- Команда `flybrain fetch-data` читает `config/sources.yaml` (адрес, SHA-256 и путь каждого файла), качает только то, чего нет или что не совпало по сумме, и пишет в `data/raw/shiu/` (файлы Shiu) и `data/raw/flywire/` (аннотации). Качается во временный файл `*.part`; сумма сверяется до переименования, поэтому при несовпадении в `data/raw/` ничего не остаётся, а команда завершается с ошибкой.
- Адреса — `raw.githubusercontent.com` с полным коммитом в пути (Shiu — `91bdd1e…`, аннотации — `a83b277…`). Новых зависимостей для скачивания нет, кроме `pyyaml` для чтения конфигурации.
- Сводка в конце считается по скачанным файлам, а не печатается из конфигурации.

**Что обнаружили при первом запуске.** Суммы `Completeness_783.csv`, `model.py` и `utils.py` из фазы исследования были посчитаны для копий, склонированных в Windows: git при клонировании заменил в них переводы строк `LF` на `CRLF`. Настоящие байты в репозитории — с `LF`. Проверено: если убрать `\r` из старых копий, их сумма совпадает с суммой скачанных файлов (`tr -d '\r'` для всех трёх). То есть по содержанию файлы те же, различаются только переводы строк. `Connectivity_783.parquet` и таблица аннотаций (двоичные/не затронутые) совпали со старыми суммами с первого раза. В `config/sources.yaml` и `docs/DATA.md` записаны суммы настоящих байтов. Это исправление ошибки в нашей записи, а не подгонка: значения проверены независимо от скачивания.

**Следствия.** Копии в `.research/` — с `CRLF`, и сравнивать с ними побайтно нельзя. Для C4 используем `data/raw/shiu/model.py` из C2. Строки `LF`/`CRLF` не влияют на выполнение Python.

## D-025. Подготовка данных (C3): таблица нейронов, матрица связей, группы
*20.10.2026, коммит C3*

**Решение.**
- Команда `flybrain build-data` собирает в `data/processed/` пять файлов: таблицу нейронов `neurons.parquet`, матрицу связей `connectivity.npz`, группы `groups.json`, картинку `preview.png` и справку о сборке `build_info.json`. Форматы описаны в [DATA.md](DATA.md), раздел 5. Перед работой команда сверяет контрольные суммы исходных файлов. Если файла нет или он другой, она просит выполнить `fetch-data` и ничего не пишет.
- **Таблица нейронов.** Номер строки — внутренний номер нейрона, в порядке `Completeness_783.csv`, как в модели Shiu.
  - Точка нейрона — тело клетки, а если его нет, то опорная точка (D-016).
  - Координаты в микрометрах. X отражён простой сменой знака: `x_um = −pos_x × 0,004`. Без сдвига, поэтому исходное значение легко вернуть.
  - Оси: x растёт к **левой** стороне мухи, y — сверху вниз, z — спереди назад.
  - Проверено по данным: «левые» по таблице нейроны лежат в среднем при x = −315 мкм, «правые» — при −730 мкм, середина мозга — около −525 мкм. Обонятельные нейроны усика (перед мозга) — при z ≈ 33 мкм, тела клеток грибовидных тел (зад) — при z ≈ 190 мкм.
  - До отражения система координат была зеркальной (левой). После отражения она обычная, правая: картинка мозга не вывернута наизнанку.
- **Знак нейрона берём из файла связей Shiu** (столбец `Excitatory`), а не вычисляем по медиатору. Медиатор храним отдельно, из таблицы аннотаций (столбец `nt`), — только для показа.
- **Матрица связей** — в виде CSR («сжатые строки»): хранятся только существующие связи, а не таблица 138 639 × 138 639.
  - Строка — нейрон-получатель; `indices` — номера отправителей (int32); `weight` — число синапсов со знаком (int16, от −2405 до 2405).
  - Вес в милливольтах не храним: умножить на 0,275 мВ — дело движка (D-005). Так данные не смешиваются с параметром модели.
  - Размер — 87 МБ, читается за доли секунды.
- **Группы нейронов** описаны в `config/neuron_groups.yaml`. Состав группы задаётся одним из трёх способов:
  - `paper_ids` — номера из статьи, у каждого статус «из статьи, номер не менялся» или «не найден в 783»;
  - `select` — отбор по таблице аннотаций;
  - `union` — объединение других групп.
- Списки из статьи сверяются **автоматически** с оригиналом Shiu: `figures.ipynb` и `sez_neurons.pickle`. Эти два файла добавлены в `config/sources.yaml` (коммит `91bdd1e`, суммы от байтов GitHub). Статусы сверяются с данными 783. Для исполнителей с отбором по типу номер из статьи обязан попасть в отбор — так проверяется, что тип выбран верно.
- Файлы Shiu читаем, не выполняя их кода. Тетрадку разбираем как текст. Файл pickle читаем так, что любая ссылка на код в нём — ошибка.
- В `groups.json` номера FlyWire записаны строками: в браузере (C7 и далее) целые числа больше 2⁵³ теряют точность.
- Картинку рисует `matplotlib` — новая зависимость; она же понадобится для графиков в C6.
- Справочные имена — в `config/names_ru.yaml`: ключевые типы клеток («MN9 — мотонейрон хоботка»), классы, стороны, медиаторы, знаки.

**Что обнаружили.**
1. **[ЧЕСТНОСТЬ]** У 6 021 нейрона (4,4 %) знак в модели Shiu не совпадает с правилом D-005 («ГАМК и глутамат тормозят»), если применить его к медиатору из нынешней таблицы аннотаций:
   - ацетилхолин, но в модели тормозит — 1 719;
   - глутамат, но возбуждает — 2 941;
   - ГАМК, но возбуждает — 1 348;
   - прочие — 13.

   Вероятная причина — Shiu брал другую версию предсказания медиатора; точнее мы не выясняли. Модель не меняем (D-005): и эталон, и движок используют знак Shiu. В подсказке (C8) будут видны оба значения: медиатор по таблице и знак в модели.

## D-026. 3D-облако нейронов (C7): сервер, страница, three.js
*20.10.2026, коммит C7*

**Решение.**
- Команда `flybrain serve` запускает сервер (FastAPI + uvicorn) по адресу `http://127.0.0.1:8765/`. Адрес `127.0.0.1` значит «только эта машина»: из сети сервер не виден. `run.bat` запускает эту команду, а браузер открывается сам, когда сервер готов. Порт можно сменить (`--port`), браузер не открывать — `--no-browser`. Если сервер уже запущен (двойной щелчок по `run.bat` дважды), второй запуск просто открывает браузер, а если порт занят чужой программой — говорит об этом по-русски.
- Сервер при старте читает `data/processed/neurons.parquet` и собирает из него двоичное облако (формат — [DATA.md](DATA.md), раздел 5.4) и описание классов. Дальше всё отдаётся из памяти: страница `/`, статические файлы `/web/…`, `/api/meta`, `/api/cloud.bin`. Если данные не подготовлены, команда печатает, какие две команды выполнить.
- Облако весит около 1,8 МБ до сжатия. На диск ничего нового не пишется.
- Страница — `web/index.html`, `web/main.js`, `web/style.css`. Без сборки и Node.js: браузер читает файлы как есть (D-015). Все ~139 тысяч точек рисуются одним вызовом видеокарты. Точка — полупрозрачный кружок: там, где нейронов много, цвета складываются и светлеют, поэтому тела клеток складываются в «кору». Яркость выбрана так, чтобы плотные зрительные доли не «выгорали» в сплошной белый цвет.
- Положения берутся из таблицы как есть (D-025). Камере сообщено, что «верх» — это −y; начальный вид спереди, чуть сверху и сбоку. Облако медленно вращается, пока вы не взяли мышь; дальше — вращение левой кнопкой, приближение колесом, сдвиг правой кнопкой, с плавным затуханием.
- Цвет по крупному классу (`super_class`) — `config/legend.yaml` (10 классов). Русские названия классов — из `config/names_ru.yaml`. Легенда показывает и число нейронов каждого класса. Если в таблице появится класс, которого нет в `legend.yaml`, сервер остановится с ошибкой, а не спрячет нейроны молча.
- **three.js 0.170.0 лежит в `web/vendor/` и в git** (два файла и лицензия, 1,3 МБ). Тест сверяет их SHA-256 с записью в `web/vendor/README.md`. В `.gitattributes` для этой папки отключена правка переводов строк, иначе сумма «поплыла» бы (урок D-024).
- В интерфейсе подписано, откуда данные (FlyWire, CC BY 4.0), что точка — тело клетки или опорная точка (D-016), и сколько нейронов не видно (14 без координат, D-025).
- Тесты: формат облака на крошечной таблице, ошибка при неизвестном классе, соответствие легенды и справочника имён, суммы three.js, ответы сервера на настоящих данных (`httpx` добавлен в группу `dev` для тестового клиента).

**Почему.** D-015: красота и подсказки проще всего в браузере. Облако отдаём двоичным массивом: 139 тысяч точек в JSON были бы в разы тяжелее и медленнее. Сжатие один раз при старте дешевле, чем при каждом запросе.

**Исключение из D-009.** D-009 говорит «чужой код в git не кладём». Здесь он всё же лежит в репозитории, потому что: этого прямо требует план C7 («закреплённая версия three.js в `web/vendor/`»); лицензия MIT совместима с нашей и текст лицензии лежит рядом; файлы маленькие и неизменяемые; и главное — страница должна открываться без интернета и без отдельной команды скачивания. Причины D-009 (GPL у Eon, лицензия таблицы аннотаций, размер данных) к three.js не относятся. Скачивание через `fetch-data` потребовало бы переделать проверки C2, а выгоды не дало бы.

**Альтернативы.**
- Подключать three.js с CDN (`cdn.jsdelivr.net`): нужен интернет и доверие к чужому серверу при каждом запуске — отвергнуто.
- Собирать страницу через Node.js и npm — лишний инструмент для не-программиста (D-015) — отвергнуто.
- Отдавать координаты в JSON — в разы тяжелее — отвергнуто. Целые числа вместо float32 (экономия вдвое) — не нужно на локальной машине; можно вернуться, если понадобится.
- Размер и яркость точек — наш выбор оформления, на данные и модель не влияют.

**Следствия.**
- Положения в браузере — те же числа, что в таблице нейронов: C8 сопоставляет точку и нейрон по её номеру.
- C8 добавит ответы про один нейрон (`/api/neuron/…`) и невидимый кадр для выбора точки под мышкой.
- Для 14 нейронов без координат (D-025) точек нет; ни подсказка, ни поиск в C8 до них не дотянутся.
- Окно браузера лишь немного шире экрана телефона: легенда стоит слева внизу и в узком окне перекрывает край облака. Это мелочь оформления для C12.
