# Данные: откуда, в каком виде, на каких условиях

Ни один из этих файлов не хранится в git. Команда `flybrain fetch-data` (коммит C2) скачивает их в `data/raw/` и сверит контрольные суммы (SHA-256) с таблицей ниже. Если сумма не совпала, значит файл изменился у автора, и команда остановится, а не продолжит молча. Адреса и суммы лежат в `config/sources.yaml`. Суммы текстовых файлов посчитаны от байтов, которые отдаёт GitHub, — см. D-024.

### 1.1. `Completeness_783.csv` — список нейронов модели

| Столбец | Тип | Смысл |
|---|---|---|
| *(индекс)* | целое 64 бит | номер нейрона в FlyWire (root ID), например `720575940660219265` |
| `Completed` | да/нет | нейрон проверен людьми (у всех строк «да») |

- 138 639 строк.
- **Порядок строк важен.** Номер строки (с нуля) — это внутренний номер нейрона в модели. На него ссылаются столбцы `*_Index` в файле связей.

### 1.2. `Connectivity_783.parquet` — связи

Формат Parquet — сжатая таблица, читается библиотекой pandas. Одна строка — одна пара «нейрон A → нейрон B», у которой есть хотя бы один синапс.

| Столбец | Смысл |
|---|---|
| `Presynaptic_ID`, `Postsynaptic_ID` | номера FlyWire отправителя и получателя |
| `Presynaptic_Index`, `Postsynaptic_Index` | их номера строк в `Completeness_783.csv` (0…138 638) |
| `Connectivity` | число синапсов в паре (от 1 до 2405) |
| `Excitatory` | +1 — отправитель возбуждающий, −1 — тормозящий |
| `Excitatory x Connectivity` | произведение двух предыдущих: «сила со знаком» |

- 15 091 983 пары, 54 492 922 синапса.
- 9 059 302 пары возбуждающие, 6 032 681 тормозящие.
- Порог по числу синапсов не применён: учтены даже одиночные синапсы, как в статье.
- Вес связи в модели = `Excitatory x Connectivity` × 0,275 мВ.

### 1.3. `Supplemental_file1_neuron_annotations.tsv` — что это за нейрон и где он

Текстовая таблица с разделителем «табуляция»; 139 248 строк; 31 столбец. Нужные нам столбцы:

| Столбец | Смысл | Пример |
|---|---|---|
| `root_id` | номер FlyWire (версия 783) | `720575940660219265` |
| `pos_x`, `pos_y`, `pos_z` | опорная точка на нейроне, в вокселях 4×4×40 нм | `109306, 50491, 3960` |
| `soma_x`, `soma_y`, `soma_z` | положение тела клетки, в тех же вокселях (у 21 144 нейронов пусто) | |
| `super_class` | крупный класс: `optic` 77 541, `central` 32 383, `sensory` 16 907, `visual_projection` 8 038, `ascending` 1 750, `descending` 1 303, `sensory_ascending` 612, `visual_centrifugal` 524, `motor` 110, `endocrine` 80 | `motor` |
| `cell_class`, `cell_sub_class` | уточнение: например `gustatory` / `sugar`, `mechanosensory` / `grooming` | |
| `cell_type` | тип клетки | `CB0701` (это MN9) |
| `hemibrain_type`, `synonyms` | другие имена из литературы | `Giant Fiber` |
| `side` | сторона **со стороны мухи** (`left`, `right`, `center`) | |
| `top_nt` | предсказанный медиатор | `acetylcholine` |
| `flow` | направление: `afferent` (вход), `intrinsic` (внутренний), `efferent` (выход) | |

**Перевод координат в микрометры:** x_мкм = `pos_x` × 0,004; y_мкм = `pos_y` × 0,004; z_мкм = `pos_z` × 0,04.

Мозг занимает примерно 90–900 мкм по x, 50–440 мкм по y и 0–280 мкм по z. Ось x идёт поперёк мозга, y — сверху вниз, z — спереди назад (приблизительно). Снимки зеркальные — см. D-011.

## 5. Подготовленные данные (`data/processed/`)

Собираются командой `flybrain build-data` (коммит C3, решение D-025) из файлов раздела 1 примерно за 10 секунд. В git не хранятся. Если поменялись `config/neuron_groups.yaml` или код подготовки, достаточно запустить команду ещё раз.

| Файл | Что внутри | Размер |
|---|---|---|
| `neurons.parquet` | таблица нейронов, одна строка — один нейрон модели | ~4 МБ |
| `connectivity.npz` | матрица связей в сжатом виде (только существующие связи) | 87 МБ |
| `groups.json` | группы стимулов и «исполнителей» с внутренними номерами | ~0,1 МБ |
| `preview.png` | облако нейронов в трёх проекциях (проверка глазами) | ~1 МБ |
| `build_info.json` | когда собрано, контрольные суммы исходных файлов и конфигов, главные числа | <1 КБ |

Сервер (`flybrain serve`, C7) не хранит на диске ничего нового: облако для браузера он собирает из `neurons.parquet` при запуске и держит в памяти (раздел 5.4).

### 5.1. `neurons.parquet`

Номер строки совпадает с внутренним номером нейрона: это порядок строк `Completeness_783.csv`, как в модели Shiu.

| Столбец | Тип | Смысл |
|---|---|---|
| `index` | int32 | внутренний номер, 0…138 638 |
| `root_id` | int64 | номер FlyWire (783) |
| `x_um`, `y_um`, `z_um` | float32 | положение точки в мкм; **X отражён**: `x_um = −x × 0,004` (D-011). Оси: x растёт к левой стороне мухи, y — сверху вниз, z — спереди назад. У 14 нейронов без аннотации — пусто |
| `pos_source` | текст | откуда точка: `soma` — тело клетки (118 086), `anchor` — опорная точка на отростке (20 539), `none` — координат нет (14), D-016 |
| `super_class`, `cell_class`, `cell_sub_class`, `cell_type`, `hemibrain_type`, `synonyms`, `side`, `flow` | текст | как в таблице аннотаций (раздел 1.3); `side` — со стороны мухи |
| `nt` | текст | предсказанный медиатор (`top_nt` из таблицы аннотаций) — только для показа |
| `sign` | int8 | знак нейрона **в модели Shiu**: +1 возбуждающий, −1 тормозящий, 0 — нет выходных связей (634 нейрона). Взят из файла связей; у 6 021 нейрона не совпадает с правилом по `nt` (D-025) |

### 5.2. `connectivity.npz`

Архив массивов NumPy; матрица в формате CSR («сжатые строки»).

| Массив | Тип | Смысл |
|---|---|---|
| `indptr` | int64, длина 138 640 | связи, входящие в нейрон `i`, лежат в позициях `indptr[i] … indptr[i+1]−1` |
| `indices` | int32, длина 15 091 983 | номер нейрона-отправителя |
| `weight` | int16 | число синапсов со знаком (`Excitatory x Connectivity` из файла Shiu), от −2405 до 2405 |
| `n_neurons` | int64 | 138 639 |

Строка — получатель, столбец — отправитель. Добавка к входу нейрона `i` от спайка отправителя `j` равна `weight × 0,275 мВ` (D-005). Сумма |`weight`| = 54 492 922 синапса.

### 5.3. `groups.json`

Разделы `stimuli` (стимулы) и `readouts` («исполнители»). У каждой группы: русское имя и пояснение, пометка `honesty_ru` (если группа выбрана не статьёй), источник (`paper`, `select` или `union`), сколько номеров было в статье и какие не найдены в 783, внутренние номера `indices` и номера FlyWire `root_ids`. Номера FlyWire записаны **строками**: в браузере целые числа больше 2⁵³ теряют точность.

### 5.4. Облако для браузера (`/api/cloud.bin`, `/api/meta`)

Не файл, а ответ сервера (C7). Собирается из `neurons.parquet`, сжимается gzip, браузер распаковывает сам.

| Часть | Тип | Смысл |
|---|---|---|
| заголовок | 2 × uint32 | число нейронов, версия формата (1) |
| положения | float32 × 3 на нейрон | `x_um, y_um, z_um` как в таблице нейронов (D-025); у нейронов без координат — нули |
| классы | uint8 на нейрон | номер крупного класса по порядку в `config/legend.yaml`; 255 — нет координат, точка не рисуется |

Порядок нейронов — внутренний номер, поэтому номер точки в браузере равен номеру нейрона. `/api/meta` — JSON: классы (русское имя, цвет, сколько нейронов), центр и радиус облака, сколько точек — тела клеток и сколько — опорные точки.

### 5.5. Поток живого мозга (`/ws/live`, WebSocket)

Не файл, а поток сервера (C9, D-033; стимулы и замедление — C10, D-034). Сервер шлёт два вида сообщений, страница — команды.

**Кадр** (двоичное сообщение, ~25 в секунду, little-endian):

| Часть | Тип | Смысл |
|---|---|---|
| версия | uint32 | формат кадра (1) |
| эпоха | uint32 | растёт на 1 при каждом «сбросе»: страница гасит всё, что было до него |
| начало, конец | 2 × float64 | границы кадра во времени модели, мс; кадры идут встык |
| скорость | float32 | во сколько раз модель медленнее реального времени, среднее за последние ~2 с (D-017) |
| n | uint32 | сколько нейронов выстрелило за кадр |
| номера | uint32 × n | внутренние номера нейронов |
| спайки | uint16 × n | сколько раз каждый из них выстрелил за кадр |

**Состояние** (текст JSON, `"type": "status"`): `state` (`waiting` — ни одной открытой страницы, `starting`, `running`, `paused`, `error`), `paused`, `epoch`, `time_ms`, `speed` (настоящая, измеренная), `device`, `message`; `stimuli` — что включено: ключ кнопки → `{"on", "hz", "side"}`; `target_speed` — цель ползунка замедления (`null` — без замедления), `slow_min` и `slow_slider_max` — границы ползунка. Приходит сразу после подключения и при каждом изменении.

**Команды страницы** (текст JSON): `{"cmd": "pause"}`, `{"cmd": "resume"}`, `{"cmd": "reset"}`, `{"cmd": "stimulus", "key": "sugar", "on": true, "hz": 100, "side": "left"}` (любое из `on`, `hz`, `side` можно не указывать; частота зажимается в 0…200 Гц; сторону, для которой у стимула нет списка, выбрать нельзя — команда отбрасывается), `{"cmd": "speed", "value": 0.05}` (показ в 0,05× реального времени; `null` — без замедления; значение зажимается в 0,02…1). Кривые команды сервер молча отбрасывает.

Описание кнопок-стимулов (какие группы на какой стороне, тексты «ⓘ») — `GET /api/stimuli`; собирается из `config/stimulus_panel.yaml` и `groups.json`.

Панель «исполнителей» (C11, D-035) — `GET /api/executors`: список из 1409 моторных и нисходящих нейронов (номер, имя, класс, сторона, тип FlyWire) и ожидания по статье для каждого стимула; собирается из `config/executors.yaml`, `groups.json` и `config/names_ru.yaml`.

Читается `load_exps` и `get_rate` из `utils.py` Shiu как есть |

| `Connectivity_783_shuffled.parquet` | связи для контроля Б7: те же столбцы, что у `Connectivity_783.parquet`, но получатели всех связей переставлены случайно (зерно `shuffle_seed`) |
| `trials/<условие>/trial_NN.npz` | один повтор: массивы `neuron` (внутренний номер, int32) и `t` (время спайка, с), `meta` (все настройки повтора в JSON — по нему продолжение проверяет, что повтор подходит), `seconds`, `peak_memory_gb`, `codegen`. Из этих файлов собираются файлы выше; благодаря им прогон можно прервать и продолжить |

| Файл | Смысл |
|---|---|
| `data/validation/<условие>.main.npz` | основной расчёт движка: `totals` — число спайков каждого нейрона за все повторы (int32, по внутреннему номеру), `key_counts` — спайки 10 ключевых нейронов по повторам (повторы × нейроны), `duration_s`, `seconds` (время расчёта), `meta` (все настройки в JSON: условие, зерно, стимулы, сумма файла связей, версия кода движка), `device`. В git не попадает |
| `data/validation/<условие>.repeat.npz` | то же с другим зерном случайных чисел — «шумовой предел» |
| `docs/VALIDATION.md` | отчёт: итоговая таблица, пункты А, Б, В, Д с сырыми числами и пояснениями. Пишется заново при каждом запуске; лежит в git |
| `docs/validation/*.png` | картинки к отчёту: `a_rates.png` (частоты, эталон против движка), `b2_counts.png` (пункт Б2), `b_key_neurons.png` (нейроны, по которым решаются пункты Б, В, Д) |

Если `meta` сохранённого расчёта совпадает с нынешними настройками, команда берёт его готовым, а не считает заново; изменился код движка, связи или условия — пересчитывает. Заставить пересчитать всё: `flybrain validate --rerun`.

## 8. Формы нейронов (`data/processed/skeletons/`, необязательно)

Собирает команда `flybrain fetch-skeletons` (коммит C12b, D-037). Она скачивает файл скелетов (раздел 3) с проверкой SHA-256 — если связь оборвётся, повторный запуск докачает недостающее, — перекладывает точки для быстрого чтения и проверяет координаты. В git ничего не попадает. Без этой папки всё работает как раньше, только флажок «Формы нейронов» в панели «Вид» бледный.

**Исходный файл** `sk_lod1_783_healed_ds2.parquet`: одна строка — одна точка скелета; 268 281 651 строк в 4 больших блоках. Форма есть у всех 138 639 нейронов модели (268 127 063 точки); ещё 154 588 точек — у нейронов FlyWire, которых нет в модели Shiu, их не берём.

| Столбец | Смысл |
|---|---|
| `neuron` | номер FlyWire (783) |
| `node_id`, `parent_id` | номер точки внутри нейрона и номер её «родителя» (−1 у корня) — так точки складываются в ветки (формат SWC) |
| `x`, `y`, `z` | положение, **нм** (в метаданных файла: `units: 1 nanometer`) |
| `radius` | толщина ветки; у нас не используется |

Скелеты построены авторами FlyWire из упрощённой объёмной модели каждой клетки (уровень детализации 1) и прорежены вдвое — это форма «в общих чертах», а не до синапса.

**Подготовленные файлы:**

| Файл | Что внутри | Размер |
|---|---|---|
| `nodes.bin` | точки всех нейронов модели подряд, нейрон за нейроном в порядке внутренних номеров; на точку 20 байт: `x, y, z` (float32, мкм, **X отражён**: `x_мкм = −x_нм / 1000`, как у облака, D-011), `node`, `parent` (int32, как в исходном файле) | 5,4 ГБ |
| `index.npz` | `start` (int64) и `count` (int32) на каждый внутренний номер: где в `nodes.bin` лежат точки нейрона; `count = 0` — формы нет | 1,7 МБ |
| `info.json` | справка: сумма исходного файла, отпечаток таблицы нейронов (порядок номеров FlyWire — скелеты подходят только к ней), сколько нейронов и точек, итоги проверки координат. Пишется последним: нет файла — подготовка не закончена | <10 КБ |

Исходный файл после подготовки для работы не нужен; его можно удалить (5 ГБ). Повторный запуск команды увидит готовую папку и ничего не скачает.

**Ответ сервера** `GET /api/neuron/{номер}/skeleton` (двоичный, little-endian; 404 — форм нет или у нейрона её нет):

| Часть | Тип | Смысл |
|---|---|---|
| версия | uint32 | 1 |
| n | uint32 | сколько точек |
| расстояние | float32 | от точки нейрона в облаке до ближайшей точки формы, мкм (NaN — у нейрона нет точки) |
| запас | uint32 | 0 |
| положения | float32 × 3 × n | мкм, X отражён — те же координаты, что у облака |
| родители | int32 × n | номер точки-родителя **в этом же списке**, −1 у корня |

В `/api/meta` добавлено `skeletons`: `{"available": true/false, "reason": почему форм нет}`.
