# Правила проекта FlyBrain (для Claude в каждом новом чате)

## Кто пользователь
Не программист. Все технические решения принимаешь сам и записываешь в `docs/DECISIONS.md`: что решили, почему, альтернативы, следствия. Объясняй простым русским языком, без жаргона, а если без термина не обойтись — объясни его. В конце работы давай точные команды, которые можно скопировать в PowerShell.

## Как устроена работа
- План этапа M1 — `docs/PLAN_M1.md`, коммиты C1…C13. Один чат — один коммит. Начинай с проверки, что предыдущие коммиты работают.
- Коммит считается сделанным, только если выполнена его «проверка глазами». Покажи пользователю, что именно он увидит и как это проверить.
- Сообщение коммита: `C<N>: <кратко по-русски>`.
- Документы — по-русски. Имена в коде (переменные, функции, файлы) — по-английски.

## Правило честности (главное)
- Модель Shiu не подгоняем: параметры из D-005, пороги проверки из D-018 зафиксированы заранее.
- Если стимул не даёт ожидаемой реакции, прямо говорим об этом пользователю и пишем в отчёт. Это нормальный итог.
- Всё, что задано не коннектомом (готовый контроллер, ручной коэффициент, наш выбор группы нейронов), помечается **[ЧЕСТНОСТЬ]** в `docs/DECISIONS.md` и подписывается в интерфейсе.

## Технические ограничения машины
- Windows 11; имя пользователя кириллицей; системная кодировка cp1251. Проект живёт только в `C:\Projects\FlyBrain` (D-001). Файлы всегда читай и пиши с явным `encoding="utf-8"` (D-021).
- Окружение — `uv` и Python 3.12; PyTorch под CUDA 13.0 для RTX 5070 Laptop, 8 ГБ (D-002). Всё работает прямо в Windows, без WSL2 (D-003).
- Данные и чужой код в git не кладём, а скачиваем с проверкой SHA-256 (D-009, `docs/DATA.md`). Код Eon Systems (GPL) не копируем.
- Стороны «левый/правый» — по таблице аннотаций (со стороны мухи); координаты при показе отражаем по X (D-011).
- `.research/` — черновики фазы исследования, не часть проекта.
